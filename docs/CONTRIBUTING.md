# Contributing to KhedmaLink

1. Create a focused branch from `main` and keep unrelated changes out of it.
2. Run the relevant backend or Flutter checks before opening a pull request.
3. Add tests for behaviour changes; authorization and invalid-state cases are
   required for marketplace workflows.
4. Update `todo.md` and relevant documentation when milestone status changes.
5. Do not commit secrets, `.env` files, generated build output, or local
   database files.

See [BRANCH_CONVENTIONS.md](BRANCH_CONVENTIONS.md) for naming conventions.
